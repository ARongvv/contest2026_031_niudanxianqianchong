## Phase 0 定位与盘点

- 目标:确定源树风格与注册点(读 tree-layouts.md),盘点硬件事实。
- 动作:收集原理图/引脚/时钟/供电约束;在工作区内全局搜同芯片同外设的已有实现(先抄再改)。
- 产出:外设清单 + 每项的参考实现路径 + 阶段顺序(按依赖)。

## Phase 1 最小系统

- 目标:boot → 串口控制台 → NSH。
- 验收:进 `nsh>` 执行内建命令(`uname -a`、`ps`)。
- 常见失败:串口无输出查波特率/USB-Serial-JTAG 使能;启动即重启查时钟与链接脚本。

## Phase 2 显示

- 目标:显示控制器 → framebuffer → `/dev/fb0`。
- probe:先跑色条验证(本仓范例 `dsi_probe`:pattern 模式验证命令通路、video 模式验证视频通路)。
- 验收:标准 fb 示例在 `/dev/fb0` 完成绘制。
- 常见失败:命令/视频模式混淆;underrun 中断干扰(esp32p4x 上与 flash 擦写冲突,见板级文件)。

## Phase 3 输入

- 目标:触摸控制器 → `/dev/input0`。
- probe:单点事件流验证(本仓范例 `gt911_probe`:输出有效 `DOWN/MOVE/UP`)。
- 验收:LVGL 输入设备接入后,导航点击与坐标方向正确。
- 常见失败:坐标原点/镜像方向;多点协议未启用时按单点收敛。

## Phase 4 音频

- 目标:codec 枚举 → 录音/播放链路(I2S/GDMA)。
- probe:codec 寄存器读写 + 单帧录放;再上 PCM 采集质量分析(工作区 `pcm-audio` 技能)。
- 验收:录制回放不破音;长时播放不冻死(注意播放/合成线程栈,esp32p4x 上 TTS 8K 栈真机冻死,提到 32K)。
- 常见失败:DMA 描述符配置、I2S 主从时钟、录放音量通路。

## Phase 5 摄像头

- 目标:传感器 → CSI/DVP RAW 数据流 → video 缓冲。
- probe:帧级验证(本仓范例 `csi_probe`:确认 DMA 数据流与调用链,见 docs 开发日志)。
- 验收:`video_test`/预览应用达到目标 FPS,数据格式(RAW 位宽)正确。
- 常见失败:RAW 位宽/行对齐、DMA 链表、传感器上电时序;数据"有但花屏"查格式,"全零"查数据面通路。

## Phase 6 网络

- 目标:以太网 MAC/PHY 直连,或 WiFi 走协处理器托管(如 ESP-Hosted,先 SDIO 枚举 → 控制面 → 数据面)。
- probe:链路 up → DHCP/DNS → 单次 HTTP/TLS 请求。
- 验收:DNS 解析 + TLS 握手稳定;云端请求不放在 UI/实时线程(阻塞网络 I/O 移出 LVGL owner 线程)。
- 常见失败:TLS 阶段失败先区分 DNS/TCP/TLS 层级再归因;协处理器固件版本与主机驱动不匹配。

## Phase 7 存储/大内存

- 目标:LittleFS/文件系统挂载、PSRAM 大资源加载。
- probe:挂载 → 写读回显 → 掉电重启后数据仍在。
- 验收:资源镜像(字体/模型)从 PSRAM 加载的启动路径可重复。
- 常见失败:分区表与镜像大小不匹配;PSRAM 搬运与 DMA 内存属性冲突(SRAM/PSRAM 放置原则见 docs 复盘文档)。

## 通用排障升级手段

按代价从低到高,一次只用一种:

1. **单变量 A/B**:一次只改 defconfig 开关、probe 参数、时钟或引脚一处。
2. **分段诊断日志**:在链路各层打印阶段日志(网络: DNS→TCP→TLS→HTTP;摄像头: 枚举→中断→DMA→帧)。
3. **模拟器对照**:goldfish/qemu 复现协议与应用逻辑,隔离"驱动问题 vs 应用问题"(结论带平台标签)。
4. **全量 clean 重建**:头文件或链接布局变更后,增量构建的陈旧对象会导致诡异蓝屏/行为异常——排障末期先 clean 再判断。
5. **栈与内存证据**:线程冻死先查栈(着色/高水位),再查堆;不要用加大栈掩盖大栈帧问题,审查最大栈帧与缓冲所有权。

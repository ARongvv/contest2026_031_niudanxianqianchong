## 1. 目的与范围

回答两个问题：

1. SC2336 采集的数据从光子到应用内存，每一步经过哪些硬件模块和软件函数；
2. 各层函数的职责边界与调用顺序，作为修改、评审和排障的对照基线。

覆盖 /dev/video0 正式通路（V4L2 + ISP RGB565）与 csi_probe 诊断通路
（RAW 旁路）的共存关系；不重复 SCCB 底层修复史。

## 2. 架构分层总览

    应用层   app/video_test（V4L2 ioctl）
             app/csi_probe（诊断，与 video0 在 Kconfig 层互斥）
    ─────────────────────────────────────────────
    框架层   nuttx/drivers/video/v4l2_cap.c → /dev/video0（零改动）
             imgdata_s（数据面）+ imgsensor_s（控制面）
    ─────────────────────────────────────────────
    适配层   chips/.../esp_mipi_csi_video.c   board/.../esp32p4_camera.c
             · imgdata_ops 实现                 · 板级私有 imgsensor_ops
             · 3 块 DMA 暂存帧 + memcpy 解耦    · 懒初始化：open 才上电
             · config 由板级注入                · SCCB/profile 归板级
    ─────────────────────────────────────────────
    芯片层   esp_mipi_csi.c / esp_isp.c / esp_i2c.c
             Host/Bridge/GDMA + ready/done 槽位环 + dma_paused 背压
             ISP RAW8/BGGR→RGB565（RAW_BYPASS 旁路保留）
    ─────────────────────────────────────────────

    ─────────────────────────────────────────────
    硬件     SC2336 → D-PHY → CSI-2 Host → ISP → Bridge → GDMA → PSRAM

分层判据：芯片层回答"能不能"（换板可复用），板级层回答"接在哪"
（引脚/地址/LDO/寄存器表），应用层回答"做什么"。SC2336 驱动当前为
板级私有，待接口稳定后再评估上提 drivers/ 层。

## 3. 硬件数据通路（逐段格式与速率）

| 段 | 输入 → 输出 | 关键参数 | 错误观测点 |
| --- | --- | --- | --- |
| SC2336 | 光 → Bayer BGGR RAW8 | 1024x600@30fps，载荷 147.5 Mbps | SCCB 读 ID / 回读 0x0100 |
| MIPI 串行 | RAW8 → DT=0x2a 长包 | 2 lane x 288 Mbps，占用约 26%，大量 blanking | phy_stopstate |
| D-PHY | HS 差分 → PPI 字节流 | 字节时钟 36 MHz/lane，LDO ch3 2.5V | phy_rx / rxulpsesc |
| CSI-2 Host | 拆包、ECC/CRC、lane 合并 → 32-bit IDI | DT/VC 提取 | int_st_main: ecc/crc/phy/packet |
| ISP（在线） | RAW8 BGGR → RGB565 | PLL160/2=80 MHz；帧长 614400→1228800 B | 当前仅 demosaic |
| CSI Bridge | 32-bit → 64-bit 打包；异步 FIFO 跨时钟域 | 每行 256 word64；afull=960；Bridge 是 DMA 流控方 | int_raw: overrun/fifo/discard |
| GDMA ch0 | LLI 块：153600 x 64-bit | src=Bridge 口(FIXED)，dst=暂存帧(INCR) | DMA 错误中断 |
| PSRAM 暂存帧 x3 | RGB565 1228800 B，64B 对齐 | 环形复用 | — |

要点：ISP 是唯一改变数据语义的环节（1 分量 → 3 分量）；Bridge 是
唯一位宽/时钟域转换点；Host 校验只计数不中断传输——"收到帧"与
"收到好帧"必须分开判断。

## 5. 关键设计决策

1. 双缓冲体系：框架"每帧 SET_BUF 同步驱动"与 CSI"连续流"阻抗不匹配，
   适配层自带 3 块 DMA 暂存帧 + memcpy 解耦（30fps 约 37 MB/s 拷贝）。
   零拷贝是已知演进方向，待无丢帧验收后再评估。
2. 回调下沉 HPWORK（commit 2ee213d）：ISR 只做槽位轮换/DMA 重臂/投递；
   含互斥锁的 V4L2 回调链只运行在 HPWORK/任务上下文。锁域：
   irq_lock 护槽位环，video->lock 护适配器状态，priv->lock 护生命周期。
3. 懒初始化 + 编译期互斥：bringup 只注册；上电/配置推迟到首次 open；
   video 与 csi_probe 经 Kconfig 互斥，不争抢唯一 CSI 链路。
4. ISP 配置收敛到 esp_isp.c（commit 3ebe5a5），实例所有权仍在 CSI 内；
   RAW_BYPASS 保留诊断通路；当前仅 demosaic，CCM/Gamma/LSC 未调。
5. 已知限制：帧完成恒以 result=0 上报，DMA/Bridge 错误只进统计，
   尚未映射到 V4L2_BUF_FLAG_ERROR。

# SmartHome 头文件结构体变更与陈旧对象蓝屏

排障日期：2026-09-18 ~ 2026-09-19。
适用对象：`demos/smart_home`、`configs/smart_home`、以及一切修改
`smart_home_lvgl.h` 等共享头文件的提交。

## 现象

两轮 UI 提交在真机上出现无法用代码逻辑解释的"蓝屏"死机：

- 三需求版（米家设置独立页等）：控制台停在 `build settings` 打印中途，
  截断在 `[smart_home_lvgl] bui`；
- 回退三需求、仅保留首页修复（`fa35aaa`）后：崩溃点**漂移**到
  `build network begin`；
- 控制台在行内截断、无 panic 转储输出、屏幕冻结为纯蓝，`nsh>` 无响应；
- 崩溃点不在任何被改动代码的执行路径上（改动只涉及 home/panel 构建，
  崩溃发生在 network/settings 构建）。

## 定位过程

1. **二分排障**：
   - 回退到 `ea322e0`（S1-S4 状态）→ 稳定能开机；
   - 仅保留"去虚拟设备"（`0b479d3`，只改 panel.c）→ 能开机且功能正常；
   - 仅保留"首页修复"（`fa35aaa`，改 home.c/nav.c/**lvgl.h**）→ 必崩。
2. **栈溢出假设被证伪**：把 `refresh_home` 中 1.5 KiB 的
   `devices[SMART_HOME_MILOCO_MAX_DEVICES]` 数组静态化后仍然崩溃。
3. **决定性证据来自对象文件时间戳**（`src/ui/lvgl/*.o`，构建系统把
   对象直接生成在源码目录，含 `_1`/`_2` 变体）：

   | 时间 | 事件 |
   | --- | --- |
   | 09-18 23:31 | 崩溃版构建：chat/settings/pages/agent/lvgl/style 等 .o 全部编译，**此时 `lvgl.h` 含新增的 `home_miloco_sub_label` 字段（`smart_home_lvgl_t` +8 字节）** |
   | 09-19 11:54 | git checkout 使 `lvgl.h` 回退（字段删除），但**只有 home.o/nav.o 重编** |
   | 09-19 12:11 | 测试 A：只有 panel.o 重编 |

   `lvgl.h` 当天已变化，而 chat.o 等仍停留在前夜——**make 未因头文件
   变化重编这些对象**。

## 根因

`apps/packages/demos/smart_home` 的增量构建对该应用**事实上不跟踪头文件
依赖**：`Make.dep` 中虽列出了 `smart_home_lvgl.h`，但 `lvgl.h` 变更后
make 并未重编全部依赖对象（与对象被生成在源码目录、存在 `_1`/`_2`
多变体命名的构建形态相关）。结果：

- `fa35aaa` 给 `smart_home_lvgl_t` 增加一个字段，插入点之后的成员
  全体偏移 +8 字节；
- 部分对象按"新布局"、部分按"旧布局"访问同一个结构体实例；
- 两套偏移的写入互相踩踏，破坏在改动代码执行点发生，**症状在几屏
  之后随机引爆**——崩溃点漂移、控制台行内截断、无 panic 输出，均为
  内存被踩后的硬挂表现；
- "能开机"的组合（`ea322e0` 全量重编、测试 A）是对象视图碰巧一致或
  冲突写入落在 NULL 安全位置，属运气而非代码正确。

## 处理与规矩

- 验证方式：恢复 `fa35aaa` 代码后删除全部对象强制全量重编：

  ```bash
  find demos/smart_home/src -name "*.o" -delete
  rm -f demos/smart_home/Make.dep
  ./build.sh ... # 正常启动
  ```

- **开发约定（必须遵守）**：凡修改 `smart_home_lvgl.h`、
  `smart_home_lvgl_internal.h` 或任何被多个 .c 广泛包含的头文件
  （尤其是改变结构体布局/宏定义）后，必须先删除
  `demos/smart_home/src` 下全部 `.o` 与 `Make.dep` 再构建烧录；
  增量构建结果在此应用上不可信。
- 提交涉及头文件布局变更时，在提交说明中注明"需全量重编验证"。

## 教训

- "崩溃点不在改动路径上 + 崩溃点漂移 + 控制台行内截断"三征齐现时，
  优先怀疑构建产物一致性（陈旧对象/混合布局），而不是继续审代码；
  `stat` 对象时间戳与头文件 mtime 的比对是最快的一锤定音手段；
- 二分排障时，`git checkout <commit> -- <目录>` 会把目录内所有内容
  有差异的文件一起退回，可能把"单变量实验"变成"全量回退"——
  指定具体文件列表才能保证实验只改一个变量。

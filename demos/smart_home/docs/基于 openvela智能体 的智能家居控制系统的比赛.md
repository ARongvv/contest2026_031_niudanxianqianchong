# 基于 openvela 智能体的智能家居控制系统

## 赛题背景

本项目旨在基于 openvela 平台与 openvela 智能体 AI Agent 框架，实现通过自然语言控制智能家居设备的原型系统。

openvela 智能体是 openvela 生态中首个原生适配嵌入式 RTOS 的纯 C 语言 AI Agent 框架，内置完整的 ReAct（Reasoning + Acting）推理引擎和 30+ 种内置工具，支持多 LLM 后端切换、MCP 协议扩展和多设备协作，仅需 32KB Agent 核心栈即可运行。

当前大多数 AI Agent 方案依赖 GB 级内存和 Python/TypeScript 运行时，无法部署到资源受限的嵌入式设备。openvela 智能体填补了这一空白，让智能家居网关、智能音箱等设备具备"自主思考和行动"的能力——用户说一个目标，设备自动拆解需求、调用工具、完成执行。

本赛题鼓励参赛团队基于 openvela 智能体框架，聚焦智能家居场景，通过注册自定义工具（Tool）和编写技能文件（Skill），实现自然语言驱动的灯光控制、环境监测、场景自动化等功能，推动 AI Agent 在开源嵌入式生态中的实践与落地。

## 一、赛题设计

参赛团队需基于 openvela 平台与 openvela 智能体 AI Agent 框架，构建一个自然语言驱动的智能家居控制原型系统。默认使用 openvela 模拟器（QEMU goldfish-arm64）进行开发调试，也可自行适配 openvela 开发板并在真实硬件上运行。

### 初赛部分

**目标**：基于 openvela 智能体实现自然语言控制模拟智能家居设备的可运行系统。

**任务**：

| 编号 | 任务 | 说明 |
|:----:|------|------|
| 1 | 自定义工具开发 | 基于 openvela 智能体的工具注册机制，开发至少 2 个模拟与智能家居相关的自定义工具（Tool），如灯光开关控制、温湿度读取、设备状态查询等 |
| 2 | 自然语言控制闭环 | 用户通过自然语言下达指令（如"打开客厅的灯""现在室温多少度"），openvela 智能体 Agent 自主推理并调用相应工具完成操作，实现"意图理解 → 工具调用 → 结果反馈"闭环 |
| 3 | 基础要求 | 系统可运行、功能完整；提供可复现的运行说明（环境配置、LLM 后端配置、运行步骤），具备基本异常处理 |

**初赛交付物**：代码仓库、可复现文档、运行演示（视频/日志）

### 复赛部分

**目标**：在初赛基础上拓展系统能力，从以下任务中自由选做，完成越多、质量越高，得分越高。

| 编号 | 任务 | 说明 |
|:----:|------|------|
| A | 技能文件编写 | 编写 Markdown 格式的 Skill 文件，定义复杂的多步骤家居场景（如"每天早上 8 点播报天气并根据温度自动调节空调"），无需修改 C 代码即可扩展 Agent 行为 |
| B | 多设备协作 | 利用 openvela 智能体的 OpenClaw Node 协议，实现至少 2 台设备间的工具能力共享与协作（如音箱调用温湿度传感器节点的数据后控制风扇） |
| C | MCP 协议扩展 | 通过 MCP（Model Context Protocol）为 Agent 注册外部工具，实现与第三方智能家居服务的集成 |
| D | 多 LLM 后端适配 | 适配至少 2 种 LLM 后端（如 Kimi、DeepSeek、通义千问等），对比不同模型在工具调用场景下的表现 |
| E | 安全增强 | 自定义命令黑白名单策略、文件访问权限控制等安全机制，并给出测试用例 |
| F | UI 展示与交互 | 在设备端或上位机提供可视化界面，展示 Agent 的推理过程、工具调用链和家居设备状态 |
| G | 开发板适配（加分项） | 自行选择开发板适配 openvela，在真实硬件上运行并演示。适配代码需提交至代码仓库，附适配说明文档。成功适配并提交可获得额外加分 |

**复赛交付物**：代码仓库、复赛增量说明文档、演示视频/日志

1. 基于 VelaClaw 开发智能家居相关自定义工具
2. 实现自然语言控制智能家居的端到端闭环系统
3. 多步骤家居场景技能开发与多设备协作能力拓展
4. 多 LLM 后端适配、第三方服务集成与系统安全增强
5. 可视化交互界面开发与 openvela 平台硬件适配
